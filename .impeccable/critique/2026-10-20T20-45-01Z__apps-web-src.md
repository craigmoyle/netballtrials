## Priority Issues

1. **[P2] Registration section links trigger router warnings and can leave the active cue stale.** Clicking Eligibility changes the hash and reaches the target, but the nav can continue to mark Positions as current. The browser also logged React Router warnings that the anchor’s POP navigation was not created by the router.  
   **Why it matters:** The navigation’s current-state cue becomes unreliable, and console warnings signal an unsupported navigation path.  
   **Fix:** Make same-page section jumps router-safe, avoid invoking the leave-page blocker for hash-only movement, and update the active item to match the section reached. Keep the single-page form and its section links.  
   **Suggested command:** `/impeccable harden`

2. **[P2] The open mobile Event tools panel still occupies about 322px.** All three groups are visible as requested, but the menu pushes the page task down.  
   **Why it matters:** Staff may need to scan a large menu before returning to the operational task.  
   **Fix:** Keep all groups expanded, but tighten spacing and strengthen the category boundaries and current-route cue.  
   **Suggested command:** `/impeccable layout`

3. **[P3] “New event” is easy to miss on the Admin Events page.** It is a plain text link above an otherwise sparse event list.  
   **Why it matters:** Creating an event is the main action on that page, but it has little visual priority.  
   **Fix:** Give New event a clear primary-action treatment while keeping the event list scannable.  
   **Suggested command:** `/impeccable layout`
