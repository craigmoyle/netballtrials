## Design Specificity Verdict

**LLM assessment:** The workflows and information model are specific to Chisholm’s trials: event registration, player Number, court colors, rounds and selector sheets. The blue/plum identity anchors the interface. The public pages, especially the registration form, still feel like a generic form-based app; their strongest opportunity is to explain netball choices and eligibility right where parents need them.

**Deterministic scan:** The scan found **23 advisory findings** in `apps/web/src/styles.css`: 17 undocumented colors at lines 31, 37, 158, 197–201, 270, 278 and 281; and six type sizes outside the documented scale at lines 136, 198, 235, 254, 259 and 330. The colors include focus, placeholder, validation, scanner and planner-state colors; the type sizes are used in compact or responsive views. These are documentation coverage gaps, not evidence that the treatments are visually wrong. No higher-severity findings appeared.

**Browser evidence:** The detector script injected successfully on the home page, registration page, volunteer check-in and Admin sign-in. Its console summaries reported two anti-patterns on the home page and one on each other page. This harness only provides headless Playwright, so there is no `[Human]` tab or reliable user-visible overlay. The live server was stopped; its cleanup helper reported a missing config while removing a script tag, but the process and port are stopped and no injected reference or extra source changes remain.

## Overall Impression

The app understands the trial-day workflow and has a readable, coherent visual foundation. The biggest risk is not aesthetics: a parent can unintentionally submit GS as the player’s first preference, and later be asked to attest to eligibility details several screens above.

## What’s Working

- Contrast is strong in sampled combinations: ink on blue was 5.00:1, ink on canvas 15.43:1, and white on plum 13.92:1. Form controls are about 44px high, with visible keyboard focus.
- The home listing shows date, venue, arrival, first whistle and fee before registration. The inspected mobile views had no app-level horizontal overflow.
- Admin planning includes team, position, statistics and player-reference views, along with revision status and reversible edit flows. Selector sheets reflect the actual court/team structure.

## Priority Issues

1. **[P1] First position silently defaults to GS.** `RegisterPage` initializes the first preference as GS and offers no “Choose a position” placeholder. A parent who doesn’t notice the select submits GS as the top choice, which can distort preference data and planning. **Fix:** start empty, require an explicit choice and make that requirement visible. **Suggested command:** `/impeccable clarify`.
2. **[P1] Registration is a long memory test.** On mobile, the form is about 1,880px tall, with eligibility and privacy copy before the fields, no section grouping, and a final checkbox that refers back to requirements “above.” Parents may miss a section or attest without rereading. **Fix:** group player, guardian, position and declaration fields; repeat a concise eligibility reminder by the checkbox; explain the position abbreviations. **Suggested command:** `/impeccable layout`.
3. **[P2] Check-in entry lacks context.** Volunteers see “Committee member” and “Volunteer” links that lead to the same form, then must enter an Event ID and PIN without guidance on where to find the ID. **Fix:** consolidate the duplicate links and explain how to get the Event ID, or provide an event-specific entry point. **Suggested command:** `/impeccable clarify`.
4. **[P2] Event dates change format between listing and registration.** The home page uses “12 September 2027,” while registration shows `2027-09-12`. Parents have to re-parse the date at the point of commitment. **Fix:** use the same Australian-localized date formatting on both pages. **Suggested command:** `/impeccable clarify`.

## Persona Red Flags

**Jordan (first-time parent):** The eligibility statement appears before the long form, while the confirmation is at the bottom. Jordan must scroll back to check the rule. The first-position select already shows GS, and the position abbreviations have no inline explanation.

**Alex (committee power user):** On a 61-player roster, the early-leaver selector is a scrollable list without search/filter. Finding several players takes more scanning than necessary.

**Sam (keyboard/screen-reader user):** Labels, focus styling and registration error-summary focus are good foundations. The position choices are still presented as unexplained abbreviations, and GS is announced as the current value without indicating that it is a default. Sampled contrast passed; screen-reader and zoom behavior still warrant an accessibility audit.

## Minor Observations

- At 390px, the public header wraps “Volunteer” onto a second row. There was no app-level overflow, but the header takes more vertical space.
- The public home page returned a 404 for `/favicon.ico`.
- The general Admin screenshot available for review is stale and was excluded. The Full Game List screenshot matches its source revision but uses an older, smaller fixture.

## Questions to Consider

- Whether the first position should start unselected.
- Whether registration should remain a single page with clear sections or become a short staged flow.
- Whether check-in can carry event context so volunteers don’t have to locate an Event ID.
